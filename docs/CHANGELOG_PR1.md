# PR #1 变更说明

分支 `cursor/fix-stale-pool-quotes-f138`。下面按合入顺序说明改了什么、当时怎么核对。文末是 Mac 上的启动命令和限制。

## 首页价格停在建池日

标的池超过 20 只后，首页直接读 `etf_instrument` 里的快照，不再拉行情。515220 因此一直显示 2026-09-11 的收盘 **1.292 / -2.05%**，而当时腾讯、新浪的最新价是 **1.303 / +0.85%**。

直出标的池时，用新浪分类行情的「最新价」「涨跌幅」覆盖内存和数据库。没有最新价时不用昨收顶上。行情接口失败时仍返回原快照。

核对：`backend/tests/test_services/test_pool_quote_refresh.py` 里 515220 从 1.292 被覆盖成 1.303。线上 `https://qt.gtimg.cn/q=sh515220` 返回 200，最新价字段为 1.303。

## 数据库：默认 SQLite，可切 MySQL

## 开盘前的 0 价和 0 成交额

新浪在开盘前、收盘后和休市日会把最新价、成交额报成 0。这会把已保存的价格覆盖成 0，也会让「今日成交额 ≥ 门槛」把整个池子滤空。全市场列表没有超时，接口可以一直挂着。

现在的规则：

- 连续竞价（交易日 09:30 至 15:00）里，只拒绝非正价格。
- 这段时间之外，最新价 ≤ 0 或成交额为 0 都视为无效。成交额这一列缺失时，不据此把正常报价判无效。
- 无效行情不覆盖已有的正价格和涨跌幅。库里的价格已经是 0，或全量重建时，改用本地日 K 最后一根收盘、其涨跌幅和成交额，并把该 K 线的日期标在卡片上。
- 全市场新浪请求超时 10 秒。超时或失败时返回已落库的池子，不再继续等。

核对：`test_pool_quote_refresh.py` 中开盘前保留 1.303、空价格回退到 2026-10-14 收盘、0 成交额仍能入库、`requests.get` 的 `timeout` 为 10 且失败时不调用 `save_pool`。`test_market_clock.py` 覆盖开盘前、周末和盘中三种判断。本次在 SQLite 上重跑全量 `backend/tests`：**204 通过，1 跳过**（仍是那条只在 MySQL 下执行的错误密码用例）。

## 使用时要注意

- 已有的 SQLite 文件靠 `CREATE TABLE IF NOT EXISTS` 建表。以后表结构变了，不会自动迁移旧文件。需要新结构时，先停服务，把 `data/etf_grid.sqlite` 移走，再启动让它重建。MySQL 上的 `ALTER` 备注语句在 SQLite 上会跳过。
- SQLite 启动锁是本机文件锁，只防止同一台机器上的两个进程同时做启动同步。多台机器要互斥时用 MySQL 的 `GET_LOCK`。
- 开盘前、收盘后和休市日，新浪仍可能给出 0 价和 0 成交额。程序会忽略它们并显示上一根有效收盘和日期。连续竞价开始后才会用新的最新价覆盖。
- 本地标的不足 20 只时，第一次会拉全市场列表，最多等 10 秒，超时就用已有数据。之后 10 分钟内首页再打开不再重拉，除非地址带 `refresh=1`。新浪慢的时候，这一次仍可能多等 10 秒。
- 本机调试器默认关闭。需要 Werkzeug 调试器时再设 `FLASK_DEBUG=1`。`start.sh` 监听 `127.0.0.1`，不要对公网暴露。
- `TUSHARE_TOKEN` 必须是至少 16 位的真实 token，应用才能启动。测试收集时如果环境里没有这个变量，会临时用占位值，不会改你的 `.env`。
- 没有交易日历缓存时，休市判断只排除周末。当年交易日历要能访问网络才会更新。
- 回测锚点 ATR 没有窗口前的预热 K 线。频率偏好只缩放默认 ATR 倍数，底仓仍是 50%。

## 第二轮

同一条分支上的第二轮核对。每一项单独提交。

### 空库不再显示 256/358

空的或刚重建的 SQLite 里雷达是空的，徽章却用 `length || 256` 显示 256/358。标的池要有本地日 K，日 K 同步又只扫已有池子，两边互相等。

现在徽章按实际加载行数显示，0 就是 0，并提示「正在回补日K」。启动时先取市场列表，再给这些代码补日 K。页面和脚本里的 256、358、537 写死数字已去掉。

核对：空库 `GET /api/etf/pool` 返回 `total=0`、`backfilling=true`。成熟度计数用例确认 0 不会被换成 256。

### 收盘前不落当天未走完的 K 线

`universe_bar_sync_service` 的备用日 K 会把当天还没走完的 K 线写进 `etf_daily_bar`，ATR 和 20 日成交额被这根半成品带偏。

交易日 15:00 前，日期等于今天的那根 K 线不入库，也不参与 ATR 和 20 日均额。全量历史同步返回的数据同样去掉这根，和库里保存的一致。15:00 之后才算完成。

核对：11:30 的样本只留到前一交易日，均额仍按已完成的 20 根算；15:00 之后当天这根才计入。

### 腾讯备用行情带上上海时间

分析页的腾讯备用报价没有交易日，锚点会把今天的价格标成昨天。页头「当前价格」其实是回测窗口最后一根收盘。

备用报价现在带上海时间。09:30 前日期回到上一交易日。页头和回测卡改成「窗口末日收盘」。

核对：2026-10-15 11:20 的备用报价日期是当天，09:00 前是前一交易日。

### 细分赛道代表可以换下一名

网格适合度榜每个细分只留成交额最高的一只。「医药」不在关键词里，512010 没有细分。代表没过门槛时，后面的不再试。

「医药」排在中药、生物疫苗、医疗器械、创新药之后，512010 归到医药。代表按成交额从高到低试，第一只没入榜就试下一只，入榜的那只成为该细分的种子。

核对：中药龙头样本不够时，次席入榜并成为种子；512010 进入医药。

### AkShare 缓存不再跟着当前目录

缓存写成相对当前目录的 `../cache/akshare`。在仓库根目录启动会碰到权限错误。

现在默认是仓库根下的 `cache/akshare`。`AKSHARE_CACHE_DIR` 可以改，相对路径仍相对仓库根，不相对当前目录。

核对：测试把工作目录换到临时目录后，解析结果仍落在仓库的 `cache/akshare`。

### 文案跟实际库和数据源

页面上的 MySQL、Tushare、「每日收盘后」、「全市场 537 只」改成当前 `DB_TYPE`、腾讯财经 / 东方财富，以及接口返回的数量。`DB_TYPE=mysql` 时显示「本机 MySQL」。连不上 MySQL 仍然直接失败，不会改回 SQLite。

### 压力沙盘标出最深档

标题旁显示当前网格最深买档相对锚点的跌幅，例如「当前最深网格 -12.6%」。

首页和参数表单的默认步长仍是 ATR，对应按日做 T。已经有名为「E大经典守株版」的预设，锁定固定步长 5% / 15% / 30%。没有把全局默认改成 E 大。沙盘显示的是这次实际铺出来的网格，不是另一套默认值。

核对：价格 10、买档 9/8/7 时标签为 -30.0%。守株预设的步长断言仍是 5 和 30。

### 雷达 ATR 下限可以降到 1.0

默认仍是 1.5%。页面可以选「放宽到 1.0%」，也可以勾选「黄金/大宗商品豁免到 1.0%」（默认不勾）。接口把低于 1.0 的请求抬回 1.0。豁免只放行赛道为「大宗商品」且 ATR 不低于 1.0% 的标的。

已经按 1.5% 建过的库里，没有 1.0% 到 1.5% 的名字。它们要等下一次全量重建才会入库。切换门槛不会自动带 `refresh=1`，避免每次点击都打新浪。

核对：黄金 ETF ATR 1.2 在 1.5 门槛下被排除，豁免打开后留下；医药 ATR 1.2 只有门槛降到 1.0 才出现。

### 雷达分数和胜率

原先分数挤在 98 附近，胜率把所有卖出都算进去，所以接近 100%。

有网格适合度榜的 ATR 年化做 T 现金收益时，按这个收益排序和打分。没有时用价差和成交额，不再封顶到 98。胜率只统计买入网格上已经闭环、扣过双边费用后仍盈利的卖出。只有底仓高抛时不给胜率。最大回撤跟在胜率旁边。

### 390 像素和暗色

顶栏在窄屏改成两行，不再把导航和按钮挤出屏幕。适合度表格在卡片内横向滚动，页面本身保持 390 像素宽。顶栏、页底、分析页头部和报告底色在系统深色模式下使用深色表面。

核对：用无头浏览器把视口设为 390×844，首页、适合度榜、分析页的文档滚动宽度都是 390。适合度表在卡片内从 322 像素滚到 704 像素。深色模式下顶栏背景是 `rgb(17, 24, 39)`，分析页头部是 `rgb(31, 41, 55)`。

### 东财断开后改走腾讯，小池子不再每次重拉全市场

第一次分析会等东方财富断开，下一次分析又等一次。连续失败两次后，东财暂停约 60 秒，这期间日 K 和现货走腾讯，到点再试东财。

首页在标的不足 20 只时，以前每次打开都重建全市场列表。现在 10 分钟内直接返回已落库结果。`refresh=1` 和启动时的强制重建不受这 10 分钟限制。满 20 只时仍按原来的方式覆盖最新价。

核对：第三次日 K 请求不再调用东财；熔断打开后现货接口也不再调用。小池子连续读取时全市场列表只拉一次，冷却结束后或 `force_refresh` 才会再拉。
