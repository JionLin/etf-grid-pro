## 第一章：系统业务定位与核心边界

### 1.1 核心业务目标
本系统专注于为 A 股交易者提供 **ETF 自动化网格交易策略设计、参数自适应推演与历史真实撮合回测**：
- **赚取的收益来源**：收割标的在箱体震荡与中短期情绪起伏过程中的**“无休止波动差价现金流”**。
- **解决的交易痛点**：消除长期死拿“频繁坐过山车、有浮盈没落袋”的焦虑感；杜绝传统单层网格“暴涨卖飞踏空”与“单边阴跌底部资金钝化”两大死穴。

### 1.2 关键业务边界与免责约定
1. **非预测性策略**：本系统不预测标的未来多空走势，不提供择时买卖点荐股；
2. **不提供估值模型**：系统严禁提供指数估值温度计或股债利差底仓建议；“大网（估值防守）”仅代表价格间距更宽的防御轨，非基本面估值；
3. **标的池护城河**：自动剔除上市未满 3 年次新标的、20 日成交额不足 3,000 万元及波幅低于 1.5% 的死水标的；
4. **交易制度契约**：严格遵循 A 股现行 **T+1 隔夜解冻** 约束（跨境/货币/债券等 T+0 品种独立支持）、**100 股向下整百对齐** 申报规则、以及 **万分之 1 佣金 + 最低 0.20 元保底（免5）** 真实券商摩擦。

## 第三章：立体复合三轨资金分配与网格步长模型

### 3.1 资金结构 (50:50 核心比例)
总投资资金 $C_{\text{total}}$ 严格拆解为底仓与流动金两部分：
1. **初始底仓资金 ($C_{\text{base}}$)**：
   $$C_{\text{base}} = \left\lfloor \frac{C_{\text{total}} \times 0.5}{P_0 \times 100} \right\rfloor \times 100 \times P_0$$
   底仓股数向下整除 100 股，为上涨卖出提供初始筹码弹药。
2. **流动挂单备用金 ($C_{\text{liquid}}$)**：
   $$C_{\text{liquid}} = C_{\text{total}} - C_{\text{base}}$$
   流动金在小网、中网、大网之间按 **20% : 35% : 45%** 分配：
   - **🟢 小网 (20% 流动金)**：单边 5 档，负责日内/周线高频穿梭做 T，保障日常现金流；
   - **🔵 中网 (35% 流动金)**：单边 3 档，主力捕获月度中级波段，贡献核心价差利润；
   - **🟣 大网 (45% 流动金)**：单边 2 档，重兵把守深跌极端行情，严防黑天鹅击穿。

### 3.2 两种步长模式
- **★ 🌊 ATR 动态自适应模式（默认）**：
  基于 14 日 Welles Wilder ATR 动态折算：
  - 小网：$0.6 \times \text{ATR}$（覆盖约 68% 高频振幅）；
  - 中网：$1.2 \times \text{ATR}$；
  - 大网：$2.5 \times \text{ATR}$。档位纵深约为档数 × 步长（默认乘数下大约 -7% 到 -12%），**不是** -60%。
- **🏛️ E大原版经典大步长（5% / 15% / 30% · 宏观守株待兔）**：
  - 小网固定 5.0%（5 档覆盖 25% 调整）；
  - 中网固定 15.0%（3 档覆盖 45% 熊市）；
  - 大网固定 30.0%（经典 30%×2 档，几何下潜约至 -60%）。
- **加码协议分两套**：公众号 10 万三轨案例为等额（加码 0）；站点默认与矩阵横评为倒金字塔 10%、本金 3 万。沙盘 `0% ~ -60%` 滑块是压力区间，不是 ATR 实测档位。

### 3.3 复合阶梯唯一事实源 (Single Source of Truth)
顶层价格区间 $[\min(P_{\text{buy}}), \max(P_{\text{sell}})]$、资金占用率和主步长展示，**一律从生成后的多轨合并阶梯（Merged Ladder）中向上投影获取**，禁止脱离阶梯单独硬编码计算。

## 第四章：独创业务一 · 模式 B 利润蓄水池与 0 成本免费股沉淀

针对 A 股 100 股（1手）最小交易申报限制，小额网格（如 3~10 万）单笔做 T 差价（15~30元）无法一次买满 1 手。系统自创 **“0 成本利润蓄水池状态机”**：

```
做 T 卖出成功
     │
     ▼
计算该笔净利润: P_net = 卖出金额 - 买入成本 - 双边佣金
     │
     ▼
汇入蓄水池: ProfitPool = ProfitPool + P_net
     │
     ▼
判定条件: ProfitPool >= P_target * 100 ？
     ├── 否 ──▶ 零钱结存在蓄水池中，等待后续做 T 滚存
     └── 是 ──▶ 【自动触发转增 0 成本份额】
                • 转增股数: N = floor(ProfitPool / (P_target * 100)) * 100
                • 扣减池金: ProfitPool = ProfitPool - N * P_target
                • 增加永久免费股: FreeShares = FreeShares + N (成本恒为 ¥0.000)
```

- **业务断言**：
  1. 免费份额持仓成本恒为 `¥0.000 / 股`；
  2. 免费份额永久锁仓、长线持有，不参与后续普通网格的高抛卖出，彻底攻克大牛市“卖飞踏空”的死穴；
  3. 模式 A（现金留存）与模式 B（留股滚存）支持一键切换。

## 第五章：独创业务二 · 倒金字塔逐格加码数学模型

为攻克下跌深水区“等额买入资金钝化”的痛点，系统在买入端支持倒金字塔逐格加码 $r \in [0.05, 0.20]$：
- **档位权重**：买 $i$ 档权重为 $w_i = (1 + r)^{i-1}$（$i=1$ 为最浅档，加码到最深档）；
- **档位资金**：$\text{Alloc}_i = C_{\text{rail}} \times \frac{w_i}{\sum w_j}$；
- **档位股数**：$\text{Shares}_i = \max\left(100, \left\lfloor \frac{\text{Alloc}_i}{P_{\text{buy}, i} \times 100} \right\rfloor \times 100\right)$；
- **业务断言**：加码模式下各轨道买单总金额不得超出 $C_{\text{rail}}$ 资金池；越深档位股数严格单调递增，底部分配股数比等额模式提升 30%~50%。

## 第六章：独创业务三 · A 股真实 T+1 回测撮合引擎与 GridSlot 状态机

### 6.1 有状态槽位模型 (GridSlot)
回测拒绝粗糙的买卖计数累加，为每个档位实例化唯一的 `GridSlot` 对象：
- **状态转移**：`WAIT_BUY`（空闲监听买入） <---> `WAIT_SELL`（持仓监听卖出）；
- **买卖精准配对**：每次卖出撮合必须绑定其入场的唯一 `buy_cost` 与 `buy_fee`，输出实打实的逐笔纯利润，彻底根除预估收益破折号 `-`；
- **小网 5 格上限硬熔断 (Circuit Breaker)**：
  小网处于 `WAIT_SELL` 状态的槽位数绝对上限为 5 格。在单边暴跌中，小网持仓档位达到 5 格后触发硬熔断，强制拒绝小网继续补仓，将子弹保留给中网和大网在更低点承接。

### 6.2 账户 T+1 隔夜解冻
1. **盘前解冻**：
   $$\text{AvailableShares}_t = \text{AvailableShares}_{t-1} + \text{FrozenShares}_{t-1}, \quad \text{FrozenShares}_t = 0$$
2. **盘中撮合**：
   - 当日买入成交计入 $\text{FrozenShares}_t$，当日严禁卖出（T+0 标的除外）；
   - 卖出仅能消耗 $\text{AvailableShares}_t$；
3. **消除未来函数**：
   回测开网基准价 $P_0$ 严格取自**回测区间首个交易日的开盘价**（$P_0 = \text{Open}_0$），严禁使用回测期末或最新市价展开历史网格。

## 第七章：独创业务四 · 资金全链路 100% 对账闭环与三层穿透全景

回测期末对账必须实现 **100% 平账无偏差**：

### 7.1 资产估值恒等式
在任意交易日收盘，系统总资产必须严格满足：
$$\text{TotalEquity}_t \equiv \text{Cash}_t + (\text{AvailableShares}_t + \text{FrozenShares}_t) \times C_t + \text{FreeShares}_t \times C_t + \text{ProfitPool}_t$$

### 7.2 留利润模式三维收益穿透平账
期末净利润必须完全拆解为以下三部分且总和等于期末增值：
$$\text{NetProfit} = \text{FinalEquity} - \text{InitialCapital}$$
$$\text{NetProfit} \equiv \underbrace{\text{做T落袋纯利}}_{\text{① 流水纯价差}} + \underbrace{(\text{FreeShares} \times C_{\text{final}} - \text{转增购股总成本})}_{\text{② 免费份额持仓浮盈}} + \underbrace{\text{底仓余值变动与高抛贡献}}_{\text{③ 底仓高抛及持仓盈亏}}$$

- **业务断言**：后端必须输出对账状态，前端展示【资金全链路平账 对账闭环 100%】，误差容限小于 ¥0.01。

## 第八章：独创业务五 · 极限行情双向压力测试沙盘推演模型

系统在 `StressTestSandboxCard` 与 `stressTestCalculator.js` 中构建了毫秒级双向沙盘推演模型：

### 8.1 下跌防穿透沙盘推演 (Downside Stress Test)
交易者可滑动跌幅滑块（`0% ~ 60%`）或点击 5 大预设（`-10%`、`-20%`、`-30%`、`-40%`、`-50%`）：
1. **模拟极端价格**：$P_{\text{target}} = P_0 \times (1 - \text{Drop}\%)$；
2. **买入击穿与资金消耗**：筛选所有 $P_{\text{buy}} \ge P_{\text{target}}$ 的挂单，精确统计小/中/大各轨触发档位、吸筹股数与总资金；
3. **加权持仓成本均价**：
   $$P_{\text{avg}} = \frac{\text{底仓本金} + \sum \text{触发买单金额} + \sum \text{买入手续费}}{\text{底仓股数} + \sum \text{买入股数}}$$
4. **回本反弹对比模型**：
   - **普通死拿回本所需反弹**：$\text{Rebound}_{\text{normal}} = \frac{P_0 - P_{\text{target}}}{P_{\text{target}}} \times 100\%$
   - **网格脱困所需反弹**：$\text{Rebound}_{\text{grid}} = \frac{P_{\text{avg}} - P_{\text{target}}}{P_{\text{target}}} \times 100\%$
   - **网格领先安全垫**：$\Delta \text{Advantage} = \text{Rebound}_{\text{normal}} - \text{Rebound}_{\text{grid}}$
5. **水淹满仓哨兵**：当跌幅超出最深买单时，自动激活【🛡️ 超深水淹满仓状态】胶囊，提醒交易者资金已被安全锁定，耐心等待均值回归。

### 8.2 上涨防踏空沙盘推演 (Upside Rally Test)
支持上涨滑块（`0% ~ 60%`）或预设（`+10%`、`+20%`、`+30%`、`+50%`）：
1. **模拟极端上涨价**：$P_{\text{target}} = P_0 \times (1 + \text{Rally}\%)$；
2. **卖单逐档高抛变现**：筛选所有 $P_{\text{sell}} \le P_{\text{target}}$ 的卖单，测算回笼资金与累计做 T 差价利润；
3. **模式 B 踏空对冲核算**：
   - 测算纯差价利润沉淀出的 0 成本免费股票现值；
   - 测算卖飞后剩余底仓的增值市值；
   - 展示“高位虽然减仓，但留下的免费股与剩余筹码依然享受长牛复利”的踏空对冲报告。

## 第九章：独创业务六 · 多周期回测档案库与全市场矩阵横评

在 `BacktestArchiveView.jsx` 中，系统建立了多维档案库与横向横评系统：
1. **三大主视图自由切换**：
   - **`matrix` (多周期矩阵视图)**：横向穿透 90天/180天/1年/2年/3年/5年 的策略总收益与年化收益对比；
   - **`sectors` (11 大赛道横评视图)**：展示科技芯片、医药、大金融等各赛道代表性品种的历史做 T 战绩与排位；
   - **`records` (明细流水账视图)**：查看本地或云端沉淀的每一次历史回测任务快照；
2. **收益显示模式切换**：支持【年化收益率 (Annual)】与【累计总收益率 (Total)】一键切换；
3. **策略参数反填联动 (`onApplyParams`)**：用户在历史档案中看到心仪的历史策略时，点击即可一键将该策略的全部参数（本金、步长模式、乘数、P₀ 锚点）反填载入策略设计器；

## 第十一章：底层历史 K 线与回测数据的五重严谨校验规范

为了确保历史回测结果的绝对真实可信、杜绝“未来函数”与“假数据回测”，系统在底层建立了 **五重严密的数据校验防线**：

### 11.1 第一重：K 线物理极值与数据逻辑校验 (Bar Sanity Check)
从 MySQL `etf_daily_bar` 提取的每一条历史日 K 线数据必须无条件满足金融物理逻辑约束：
1. **价格区间自洽**：
   $$High_t \ge \max(Open_t, Close_t), \quad Low_t \le \min(Open_t, Close_t), \quad Low_t > 0$$
2. **成交量与成交额非负**：
   $$Volume_t \ge 0, \quad Amount_t \ge 0$$
3. **涨跌幅逻辑校验**：
   A 股 ETF 正常涨跌幅限制在 $\pm 10\%$（科创/创业板 ETF 限制在 $\pm 20\%$，跨境 ETF 部分无涨跌幅）。若出现单日振幅偏离超过 $\pm 30\%$ 且非拆分除权日，标记为异常脏数据予以拦截。

### 11.2 第二重：数据时效性与完整性量化体检 (Data Quality Verification)
在 `SuitabilityAnalyzer.evaluate_data_quality` 中对回测时序数据实施量化打分：
1. **数据新鲜度 (Freshness)**：
   $$\Delta \text{Days} = \text{CurrentDate} - \max(\text{Date}_{\text{bar}})$$
   - $\Delta \text{Days} \le 1$：优秀（数据非常新鲜）；
   - $\Delta \text{Days} \le 3$：良好（包含周末正常休市）；
   - $\Delta \text{Days} > 3$：发出【数据需要更新】告警，阻断无感过时回测。
2. **数据完整性 (Completeness)**：
   $$\text{MissingRate} = \frac{\sum \text{NullCells}}{N_{\text{rows}} \times N_{\text{cols}}}$$
   - 缺失率 $< 1\%$ 评定为优秀，超过 $5\%$ 触发数据修复阻断。
3. **停牌与有效交易日清洗**：
   自动剔除成交量 $Volume_t = 0$ 的非正常停牌日，确保回测时间轴完全由**真实撮合成交日**构成，避免停牌日虚假产生网格资金占用利息。

### 11.3 第三重：样本周期跨度与日历日偏差容忍校验 (Sample Horizon Check)
在 `grid_fit_service.py` 适合度榜单标准化 5 年协议中：
- **理论日历日跨度**：$\text{PROTOCOL\_WINDOW\_DAYS} = 1825$ 天；
- **A 股日历偏差容忍底线**：
  $$\text{FULL\_SAMPLE\_FLOOR\_DAYS} = 1800 \text{ 天}$$
  由于 A 股周末与法定节假日休市，真实 5 年日 K 线首尾自然跨度通常在 1,815 ~ 1,822 天。系统设定 1,800 天容忍底线，严禁将满足真实 5 年的标的误判为次新；
- **短样本底线**：
  $$\text{SHORT\_SAMPLE\_FLOOR\_DAYS} = 1095 \text{ 天 (3年)}$$
  上市时间处于 1,095 ~ 1,800 天的标的，自动被打上【短样本】标记，强制隔离在短样本区，严禁污染 5 年牛熊成熟榜单；
- **回撤超线熔断阈值（可配置）**：
  $$\text{DRAWDOWN\_CEILING} = \text{float}(\text{os.environ.get}("DRAWDOWN\_CEILING", 60.0))$$
  系统回撤超线熔断基准设为 **60.0%**（且支持通过环境变量动态调节），回测期间最大回撤超过该值的标的，自动移入【回撤超线】风险警示区。

### 11.4 第四重：防未来函数与回测锚点因果律校验 (No Look-Ahead Bias)
1. **开网基准锚点 $P_0$ 因果隔离**：
   回测引擎展开三轨网格的初始价格基准 $P_0$，必须无条件取自**该回测时序窗口第 0 天的真实开盘价**（$P_0 = Open_0$）。绝对严禁使用回测结束时的最新价格或区间内极值均价反向铺网；
2. **当日成交因果顺序**：
   日内撮合判定中，必须基于历史真实行情柱的 $High_t$ 与 $Low_t$ 触发。先判定冲高卖出、再判定下探买入，卖出仅能消耗开盘前已有的可用持仓，当日买入筹码当日坚决冻结。

### 11.5 第五重：资金守恒与无中生有平账校验 (Financial Conservation Audit)
回测运行过程中的每一个推进日及回测期末，必须进行无容忍平账校验：
1. **交易股数整数倍性**：所有产生买卖记录的交易股数必须严格满足：
   $$\text{Shares} \pmod{100} \equiv 0$$
2. **券商佣金保底摩擦**：每一笔交易产生的扣费必须满足：
   $$\text{Fee} \ge 0.20 \text{ 元}$$
3. **资金守恒对账闭环**：
   $$\left| \text{FinalEquity} - (\text{Cash} + \text{PositionValue} + \text{FreeSharesValue} + \text{ProfitPool}) \right| \le 0.01 \text{ 元}$$
   如出现资金差额大于 1 分钱，判定为回测引擎算法出现“凭空印钱”或“资金神秘漏损”重大金融 Bug。

- 点击【分享报告】后，系统将当前所有关键微调参数紧凑序列化为 QueryString：
  `?capital=30000&grid=geometric&risk=balanced&adjustment=1&stepMode=atr&days=180&scaling=0&reinvest=pool_shares`
- 写入剪贴板并弹出 Toast【报告链接已复制，他人打开即可一键还原当前所有策略参数与回测！】；
- 接收端页面加载时，必须无条件优先解析 URL QueryString 覆盖默认值。

### 13.3 统一格式化契约 (`shared/utils/format.js`)
全站所有涉及金额、百分比、日期的 DOM 渲染必须遵循：
- **金额**：必须使用 `Intl.NumberFormat('zh-CN', { style: 'currency', currency: 'CNY' })`，如 `¥30,000` 或 `¥4.575`；
- **百分比**：必须经过 $\times 100$ 并保留 1~2 位小数附带 `%`，正数显式添加 `+` 号（如 `+3.47%`）；
- **严禁脏数据**：前端严禁向用户直接展示 `NaN`、`undefined`、`null` 或类似 `3.472918274%` 的未格式化长浮点数。

## 第十五章：多 Agent 自动化测试验收断言集 (AC-01 至 AC-17)

各专职测试 Agent 必须依据以下 17 条严格的 Acceptance Criteria (AC) 执行全栈打靶与功能验收：

| 编号 | 验收分类 | 校验方 (Agent) | 验收准则 (Acceptance Criteria) |
| :--- | :--- | :--- | :--- |
| **AC-01** | 接口参数校验 | Agent B (后端) | `POST /api/analyze` 传入非法 `totalCapital < 10000` 或 `etfCode` 错误时，必须返回 HTTP 400/422 业务 JSON，严禁抛出 Python 500。 |
| **AC-02** | 4维体检与一票否决 | Agent B & C | 针对振幅不足的标的（如银行低波 ETF），适宜度评分不得超过 60 分，且界面必须显著展示黄色/红色致命缺陷警示条。 |
| **AC-03** | 模式B转增计算 | Agent B (后端) | 模拟做 T 累计利润满 1 手时，必须精准扣除池金并增加 100 股 `FreeShares`，`next_lot_needed` 与现价严格匹配。 |
| **AC-04** | 小网 5 格硬熔断 | Agent B & D | 构造单边下跌行情，小网买满 5 档后，后续继续下跌不得再产生 `small` 买单，必须保持熔断待机。 |
| **AC-05** | T+1 规则穿透 | Agent B (后端) | 在 T+1 标的回测中，当日买入的档位在同一交易日内即便利润触碰卖出价，也绝对禁止触发卖出。 |
| **AC-06** | 资金全链路平账 | Agent D (对账) | 无论回测 90 天还是 5 年，`equity_curve` 最后一天的总资产必须与现金、持仓、免费股和池内零钱求和完全一致（误差 ≤ 0.01元）。 |
| **AC-07** | 页面交互与无错误 | Agent C (前端) | 策略工作台各预设方案切换（E大经典/ATR动态/宽网防守）、本金按钮点击，右侧与分析页面均应正确联动，Console 无未捕获 JS 报错。 |
| **AC-08** | 回测多周期时间完整性 | Agent B (后端) | 请求 90天/180天/1年/2年/3年/5年 回测接口，返回有效交易日必须与历史行情严格吻合，`start_date` 与 `end_date` 不得发生时序颠倒。 |
| **AC-09** | 防未来函数真实性 | Agent B & D | 验证回测第一笔买卖的基准铺网价格 $P_0$，必须精准等于回测首日真实开盘价 $Open_0$，不得使用未来价。 |
| **AC-10** | 适合度榜单回撤熔断 | Agent B & C | `/grid-fit` 榜单中，最大回撤超线阈值默认设为 60.0%（支持 `DRAWDOWN_CEILING` 环境变量配置）。最大回撤超出该阈值的标的必须移入【回撤超线】区，不得进入主金榜。 |
| **AC-11** | 适合度榜单短样本隔离 | Agent B & C | 上市自然日处于 1095 ~ 1800 天之间的标的，必须正确被分类至【短样本区】，严禁参与 5 年牛熊成熟榜综合排名。 |
| **AC-12** | K线物理完整性校验 | Agent B (数据) | 数据库中任意用于回测的标的 K 线，必须满足 $High \ge \max(Open, Close)$ 且 $Low \le \min(Open, Close)$，缺失率超过 5% 必须报错阻断。 |
| **AC-13** | 前端数据展示一致性 | Agent C (前端) | 页面上展示的所有核心指标（总资产、年化收益、Alpha、笔数）必须与后端接口返回的 JSON 键值严格一致，禁止出现数据割裂或舍入失真。 |
